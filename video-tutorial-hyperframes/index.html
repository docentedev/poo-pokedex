PASO 01 · COMBOBOX
ELEGIR UNA OPCIÓN

ComboBox: categoría de la carta

pokedex-view.fxml FXML

2 maxWidth="Infinity"/>
PokedexController.java JAVA
1@FXML private ComboBox<String> categoriaComboBox;
2
3// 1) Definir las opciones
4categoriaComboBox.setItems(
5 FXCollections.observableArrayList(
6 "Pokémon", "Energía"));
7
8// 2) Elegir la primera opción
9categoriaComboBox.getSelectionModel().selectFirst();

11// 3) Leer la opción elegida
12String categoria = categoriaComboBox.getValue();

Categoría:

Pokémon
Energía

Cómo funciona
1
fx:id + @FXMLMismo nombre en el FXML y en Java.
2
setItems(...)Llena la lista de opciones.
3
getValue()Lee la opción elegida (puede ser null).
4
valueProperty()Avisa cuando la selección cambia.

fx:id en el FXML y el campo @FXML del controlador deben llamarse igual: así se conectan.

setItems(...) recibe un ObservableList con las opciones; selectFirst() elige una por defecto.

getValue() devuelve la opción elegida. Si no hay selección devuelve null: valida antes de usarla.

TableView: valor estimado

pokedex-view.fxml FXML
1<TableView fx:id="cartasTable">
2 <columns>
3 <TableColumn fx:id="valorColumn"
4 text="Valor estimado"/>

PokedexController.java JAVA
1@FXML private TableView<Carta> cartasTable;
2@FXML private TableColumn<Carta, String> valorColumn;
3
4valorColumn.setCellValueFactory(dato ->
5 new SimpleStringProperty(
6 formatearMoneda(dato.getValue()
7 .calcularValorEstimado())));
8
9cartasTable.setItems(cartas);
La tabla en ejecución
CategoríaNombreValor estimado
PokémonPikachu$4.200
PokémonCharmander$3.000
EnergíaFuego$1.200
La columna azul no guarda datos: se calcula por fila.
Dos fórmulas, un método
CartaPokemon

base $3.000 · +40% si es brillante

CartaEnergia

base $1.000 · +20% si energía > 3.0

La tabla pide calcularValorEstimado() a cada objeto y el polimorfismo elige la fórmula.

TableColumn<Carta, String>: la fila es una Carta y la celda muestra un String.

setCellValueFactory recibe una función: dato.getValue() es la Carta de esa fila.

El valor no se guarda en la tabla: se pide a calcularValorEstimado() cada vez que se dibuja.

setItems(cartas) conecta la ObservableList: cualquier cambio se refleja en la tabla.

PASO 03 · CHECKBOX
MARCAR SÍ / NO

CheckBox: brillante y evolución

pokedex-view.fxml FXML
1<CheckBox fx:id="brillanteCheckBox"
2 text="Sí"/>
PokedexController.java JAVA
1@FXML private CheckBox brillanteCheckBox;
2
3// ¿Está marcado?

5 brillanteCheckBox.isSelected();

7// Apagarlo si no es Pokémon
8brillanteCheckBox.setDisable(!esPokemon);

En el formulario
✓ Brillante
✓ Evolución activa

Qué cambia al marcarlo
brillante = true

El modelo suma un bono del 40% al valor estimado.

$3.000 → $4.200

Al limpiar el formulario: setSelected(false).

Un CheckBox tiene dos estados: marcado (true) o desmarcado (false).

isSelected() devuelve el estado; se usa al construir el objeto CartaPokemon.

setDisable(...) lo apaga si la categoría no lo necesita; setSelected(false) lo limpia.

Carta es el tipo común: la variable acepta cualquier subclase. Por eso TableView<Carta> muestra Pokémon y Energía en la misma tabla.

Primero decide qué datos necesita la carta. Esa decisión define qué clase instanciar.

La variable se declara como Carta, pero el objeto real es CartaPokemon o CartaEnergia.

cartas es una ObservableList<Carta>: al agregar el objeto, la TableView lo muestra al instante.

calcularValorEstimado() se resuelve en ejecución: cada subclase usa su fórmula.
